# Локальные модели для демонстрации

Две небольшие модели работают без сети, API-ключей и загрузки весов при старте. Обученные параметры уже находятся в `artifacts/` и в `server/src/ml/model-data.ts`.

## Что обучено

**Риск:** логистическая регрессия на девяти финансовых признаках, затем sigmoid-калибровка на отдельной выборке. Это учебная симуляция риска, а не подтверждённая банковская вероятность дефолта. Цель генератора — случайное неблагоприятное событие; соответствие реальному дефолту на определённом горизонте не установлено.

**Цель финансирования:** multinomial naive Bayes на словах и символьных триграммах. Это обученная модель по небольшому авторскому корпусу, а не регулярные выражения для выбора продукта. Слова и триграммы извлекаются детерминированно, их веса обучаются на 98 фразах. При недостаточной уверенности модель возвращает `other` и предлагает уточнение. Пользователь подтверждает предложенную цель.

Веса и корпус открыты в репозитории; источник и лицензия описаны в model cards. LLM в этой реализации нет. Если организаторы требуют именно LLM с открытыми весами, этот классификатор не следует представлять как выполнение такого требования.

## Воспроизведение

Из корня репозитория с Python 3.11+:

```powershell
python -m pip install -r ml/requirements.txt
$env:OPENBLAS_NUM_THREADS='1'
python ml/train.py
python -m unittest discover -s ml -p 'test_*.py'
npm --prefix server test -- src/ml/scorer.spec.ts
```

`train.py` действительно генерирует независимые когорты, обучает обе модели, рассчитывает отчёты и обновляет TypeScript-параметры. Все seeds и правила генерации зафиксированы в исходнике. Можно сохранить отдельную проверочную сборку без изменения серверных весов:

```powershell
python ml/train.py --out-dir ml/reproduction-check --no-ts
```

Сравните JSON и SHA с `artifacts/`. Для воспроизведения использован NumPy 2.3.5. Параметры округляются до 12 знаков; побитовое совпадение обучения на любых BLAS/платформах не гарантируется. Сервер выполняет чистый TypeScript inference и не требует Python.

## Разделение данных и проверка

Риск: train 24 000; validation 4 000; calibration 4 000; threshold 4 000; test 6 000. У каждой выборки свой seed. Scaler и параметры логистической модели используют только train. L2 выбирается по Brier на validation. Калибровка использует calibration, отчётный порог — threshold. Test применяется для итогового отчёта. Все когорты созданы одним генератором и не являются внешней или временной проверкой.

На синтетическом test: ROC AUC **0.8361**, AP **0.6615**, Brier **0.1043**, у константного baseline Brier **0.1558**. Отчётный порог 0.15 даёт матрицу `[[3616, 1226], [266, 892]]` (строки: фактические 0/1, столбцы: прогноз 0/1). Это результат симуляции; качество на клиентах банка неизвестно. Отчётный порог служит только для метрик. Визуальные диапазоны low/medium/high 0.10/0.25 также учебные; банковские правила принимаются отдельно.

Intent: 28 отдельных тестовых фраз по известным целям, 7 примеров вне области. Правильно распознаны 18/28 фраз; 21/28 приняты без отказа, из них 18/21 верно. Все 7 посторонних примеров вызвали уточнение. Такая маленькая ручная выборка не подтверждает общую точность русского языка. Матрицы и число примеров доступны в `intent-model-card.json`.

Тесты проверяют математические метрики с одинаковыми вероятностями, независимость seeds, train-only scaler, отсутствие точных дубликатов фраз между частями корпуса, совпадение Python/TypeScript inference на golden-примерах, SHA параметров, обработку некорректных чисел и отказ на постороннем тексте.

## Контракт

`scoreRisk(input, asOf?)` принимает месячную выручку, операционные расходы, существующие ежемесячные долговые платежи в рублях (`currentDebtLoad`), дату регистрации, сумму и срок запроса, `productCode`, опциональные `overdueDays` и `taxDebt`. Расходы не должны повторно включать долговые платежи. `productCode` принимается для совместимости API, но не является обученным признаком.

Признак principal-to-surplus использует `сумма / месяцы / max(операционная прибыль, 5% выручки)`. Это показатель запроса, а не настоящий аннуитетный платёж. Аннуитет, тариф, жёсткие ограничения и статус заявки рассчитывает банковская политика отдельно.

Объяснения показывают вклад признака в логит относительно среднего train. Это объяснение учебной модели, не причинный анализ. ФНС, БКИ и другие источники не вызываются и не подтверждаются моделью.

## Артефакты

- `artifacts/risk-model.json`: scaler, коэффициенты, калибровка, версия.
- `artifacts/risk-model-card.json`: SHA, seeds, выборки, метрики, baseline, ограничения, golden-входы.
- `artifacts/intent-model.json`: словарь и обученные веса, пороги уточнения.
- `artifacts/intent-model-card.json`: SHA модели/корпуса, описание обучения, небольшие тестовые результаты.
- `intent_corpus.json`: открытый авторский корпус CC0-1.0.

Ни один артефакт не содержит реальных клиентских данных.
