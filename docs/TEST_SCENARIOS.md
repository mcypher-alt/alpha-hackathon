# Сценарии приемки

Все идентификаторы и финансовые сведения тестовые. Автоматический API-прогон: `node scripts/smoke.mjs`. Unit-проверки: `cd server && npm test`.

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Docker Compose на чистой БД | Миграции, seed, 3 healthy сервиса, кабинет и Swagger доступны |
| 2 | Подбор: станок, 3 млн, частями, 36 месяцев, без своего залога | K1 как альтернатива; K2/L3 исключены из-за залога, A1 по сумме |
| 3 | Подбор: закупки, 700 тыс, 6 месяцев, новый бизнес | A1 возможен с первого дня; неизвестные ограничения иных продуктов требуют проверки |
| 4 | Рефинансирование овердрафта на 4 млн | R1/R2 исключены с понятной причиной, нельзя подать как допустимый refi |
| 5 | Транспорт без собственного залога, согласие заложить покупку | T1 не исчезает из-за отсутствия собственного залога |
| 6 | Нераспознанная свободная цель | Уточнение, без выдуманной уверенности или автоматического отказа |
| 7 | Подбор → вход → заявка | Цель, продукт, сумма и срок переносятся; финансовые поля проверяются клиентом |
| 8 | Создать заявку и обновить страницу | Заявка, статус, условия и история сохранены в PostgreSQL |
| 9 | Одобрение → принять → подписать | Последовательные SIGNING / DISBURSED, демонстрационный договор, отсутствие реальной операции |
| 10 | Ручной анализ → запрос сведений → документ → ответ | NEED_INFO / MANUAL_REVIEW, комментарии и документ видны участникам |
| 11 | Аналитик предлагает другие условия | COUNTER_OFFER с суммой/сроком/ставкой; клиент принимает осознанно |
| 12 | Отказ с причиной | REJECTED, понятный результат и конечное состояние |
| 13 | Анонимный вызов банковской очереди | HTTP 401 |
| 14 | Клиент вызывает банковское решение | HTTP 403, состояние не изменилось |
| 15 | Другой клиент читает/меняет заявку или документ | HTTP 403/404, данные не раскрыты |
| 16 | Другой клиент подает чужой ИНН | Запрос отклонен; компания не перезаписана |
| 17 | Отрицательная сумма, неизвестный продукт, дробный срок | HTTP 400, заявка не создана |
| 18 | Подписать без принятия либо повторно | HTTP 400/409, второй выдачи нет |
| 19 | Два конкурирующих действия | Только допустимое действие проходит; журнал согласован |
| 20 | Перезапуск backend/frontend | Заявки сохраняются; повторный seed не стирает данные |
| 21 | Переключение отрасли и статуса в ленте | Другая подборка, статья открывается целиком и маркирована демонстрационной |
| 22 | Мобильная ширина и клавиатура | Нет горизонтального обрезания, поля имеют подписи, focus виден |
| 23 | Сравнить подписку | Плата отдельной строкой, полная сценарная стоимость сравнивается, экономия не гарантируется |
| 24 | Обучение / экспорт ML | Seed фиксирован, train scaler не использует test, метрики и SHA сохранены; Node inference совпадает с экспортом |

В `docs/VERIFICATION.md` перечислены выполненные проверки. Эта таблица также содержит ручные приемочные кейсы и не является утверждением, что каждый пункт автоматизирован.
