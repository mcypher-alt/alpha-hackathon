# Состояния заявки

```mermaid
stateDiagram-v2
  [*] --> DRAFT
  DRAFT --> SUBMITTED: клиент отправляет
  SUBMITTED --> VALIDATING
  VALIDATING --> ENRICHING
  ENRICHING --> SCORING
  SCORING --> APPROVED: правила и модель
  SCORING --> COUNTER_OFFER: безопасные альтернативные условия
  SCORING --> MANUAL_REVIEW: требуется аналитик
  SCORING --> REJECTED: отрицательное решение
  MANUAL_REVIEW --> NEED_INFO: запрос аналитика
  MANUAL_REVIEW --> APPROVED: решение аналитика
  MANUAL_REVIEW --> COUNTER_OFFER: другие условия
  MANUAL_REVIEW --> REJECTED: решение с причиной
  NEED_INFO --> MANUAL_REVIEW: сведения клиента
  NEED_INFO --> REJECTED: решение аналитика с причиной
  COUNTER_OFFER --> SIGNING: клиент принимает
  APPROVED --> SIGNING: клиент принимает
  SIGNING --> DISBURSED: моделирование подписи и выдачи
  REJECTED --> [*]
  DISBURSED --> [*]
```

Допустимость каждого пользовательского перехода проверяется сервером. Браузер не может произвольно выдать кредит или изменить статус. Для финальных действий проверяются текущий статус и версия записи; повторный либо конфликтующий запрос не создает вторую выдачу. История содержит автора, время, начальный и итоговый статус и комментарий.

Автоматические промежуточные состояния фиксируют выполненные проверки. При синхронной обработке они могут пройти в одном запросе, поэтому интерфейс отображает их через историю, а не искусственные задержки.

Таблица переходов в `server/src/applications/` является исполняемым источником истины; схема выше описывает основной путь MVP.
